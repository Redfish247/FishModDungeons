# FishModDungeons

- Active code: `dungeons-26.1.2` only (Mojang mappings). `dungeons-1.21.11` is frozen; never edit or mirror to it.
- Work, commit and build on `main` in this checkout. No feature branches or worktrees, even if the app started in one. Before starting: `git pull --ff-only`.
- **Commit every change** on `main` (small commits, one logical change each, new version in the message when a build is cut) so any step can be reverted. Never leave finished work uncommitted. Build only from committed main.
- **Session start: check for other running sessions** (`mcp__ccd_session_mgmt__list_sessions`, or `ListAgents`) and `git status`/`git log -5` for their uncommitted or recent work. If another session is active: note what it is touching, stay out of its files, pick a non-overlapping slice, and message it (SendMessage) when your work affects its area. Work parallel, not perpendicular: pull before building, and pick a version above any other session's.
- Version: `mod_version` in `dungeons-26.1.2/gradle.properties` (gitignored, format `X.Y.Z-26.1.2`). Bump from the DEPLOYED jar's version in the Skyblock mods folder, never from a stale file.
- Build: `./gradlew build` inside `dungeons-26.1.2`. Jar: `build/libs/FishModDungeons-<ver>-26.1.2.jar` (skip `-sources`/`-dev`).
- Deploy: copy the jar to `%APPDATA%\PrismLauncher\instances\Skyblock\minecraft\mods` and `...\instances\FishTest\minecraft\mods`, remove the old FishModDungeons jar. Only when that game is closed (overwriting a live jar crashes the client with ZipException). Check FishTest's loaded version before overwriting; other sessions deploy there too.
- **Builds are automatic, deploys are not.** A Stop hook (`tools/auto-build.ps1`, configured in the untracked `.claude/settings.json`) builds `:dungeons-26.1.2` whenever sources are newer than the newest jar; a failed build comes back to you to fix. Never copy a jar into any mods folder except through `/ship` (Eli runs it).
- Before copying any jar: `powershell -NoProfile -File tools/check-game-closed.ps1 <Skyblock|FishTest>` (exit 1 = running, skip). Read the installed version first and never install a lower one; merge other sessions' branches first (past incidents: vault Lessons Learned section 7).
- Hypixel data (nametags, areas, slime sizes, coordinates): get debug output or Eli's screenshots first. Never match guessed strings. Say "built, untested" until Eli has seen it run. Test with a default config and with/without ImmediatelyFast.
- Edit source with the Edit tool, not python/heredoc scripts (backslash loss broke regex strings four times).
- fishmod.dev worker lives in `D:\FishMod-WorkerBoard` (vault: `fishmod-worker`). Never `wrangler deploy` it without diffing against the live code first and Eli's explicit OK.
- After Eli confirms a feature works: `git push origin main:feat/<name>` then `gh pr create --head feat/<name> --base main`. One PR per feature, never merge. Do not touch the test board.
- Never script gameplay or GUI input on Hypixel (ban risk): one keypress = one click in a menu the player opened.
- Comments: one short line max. Keep colour/opacity/text customization when slimming a feature.
- **Finding code: use the index before reading or grepping files.** `python tools/code-index/where.py <terms> [-k gui|setting|uses|command|object|class|mixin|fun|lang] [-n N]` returns exact `path:line` for classes, functions, `@ConfigValue` settings, config-screen labels (gui), commands, mixins and lang keys, and which files use a setting. Player-visible feature name: search it with `-k gui`, follow to the setting, then `uses` for the feature file. It auto-rebuilds when source is newer; `python tools/code-index/build.py` forces it. Details and limits: vault page `FishModNew/02 - Architecture/Finding Code.md`. Open only the file/lines it points to. If the index misses something, fall back to Grep, then fix `build.py`.
- **Vault routing:** for the why, area maps and traps, `Codebase Map` (directory to area page), `Technical Gotchas`, `Lessons Learned`, `Working With Eli`. Read only the page for the area you touch.
- Vault: `FishModNew/` here. Read the page for the area you touch; at session end update it and log mistakes in `07 - Development/Lessons Learned.md`.
- `/ship` runs the bump, build, deploy loop.
